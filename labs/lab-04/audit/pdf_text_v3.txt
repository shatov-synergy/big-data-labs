              Рисунок 1 — Топ-20 товаров по доле транзакций

     Распределение длины транзакций (рисунок 2) скошено вправо:

                                        4
   Рисунок 2 — Распределение длины транзакций (красная линия —
                             среднее)

     Правило ассоциации X → Y («если в корзине есть набор X, то в ней же
присутствует Y») характеризуют три метрики: support (поддержка) supp(X
→ Y) = P(X ∪ Y) — доля транзакций, содержащих и X, и Y; confidence
(достоверность) conf(X → Y) = supp(X → Y)/supp(X) — условная вероятность
Y при наличии X; lift (подъём) lift(X → Y) = conf(X → Y)/supp(Y) — во
сколько раз условная вероятность Y превышает безусловную (lift > 1 —
вместе покупают чаще независимости, lift = 1 — независимы). На примере
датасета: правило {citrus fruit, other vegetables, whole milk} → {root
vegetables} имеет lift 4.1 — корнеплоды попадают в корзину с цитрусами,
овощами и молоком в несколько раз чаще случайного; confidence 45%
означает, что среди корзин с цитрусами, овощами и молоком примерно в
каждой 2-й лежат и корнеплоды; но поддержка — лишь 0.58% корзин.

             1.1 Построение правил и удаление избыточных
     Apriori запускался с широкой сеткой (support = 0,001; confidence = 0,3),
чтобы не потерять редкие, но ценные связи.
rules <- apriori(Groceries,
                 parameter = list(support = 0.001, confidence = 0.3,
                                  minlen = 2, maxlen = 4, target = "rules"))

       2 Система рекомендаций: прямой и обратный вывод
      Функция recommend_for_basket() ищет правила двух типов для товаров
переданной корзины.
      Прямой вывод — правила вида «корзина ⊆ LHS»: если товары
корзины содержатся в левой части правила, рекомендуются товары из RHS.
Логика: «кто берёт X, тот берёт и Y».

      Обратный вывод — правила вида «корзина ⊆ RHS»: товар корзины
оказался в правой части, рекомендуются товары из LHS. Логика обратная:
«кто берёт Y, обычно перед этим взял X». Это не то же самое, что прямой
вывод: ассоциативные правила несимметричны.

      Характерный пример — корзина {whole milk, other vegetables}.
Применённые правила функция ранжирует по confidence и возвращает:
tropical fruit, root vegetables, yogurt, pip fruit, butter (таблица 3). Первыми
срабатывают «зеркальные» правила, где молоко стоит справа: {tropical fruit,
root vegetables, yogurt} → {whole milk} (confidence 70%), {pip fruit, root
vegetables, other vegetables} → {whole milk} (confidence 68%) и {butter,
whipped/sour cream} → {whole milk} (confidence 66%). Прямого правила
«молоко + овощи → фрукты» в данных нет — рекомендации приходят из
LHS этих правил: это и есть обратный вывод. Асимметрия хорошо видна и на
мясных товарах: правило {meat} → {whole milk} (support 1.0%, confidence
39%, lift 1.51) в сильные не входит (lift < 2), но его сильные «соседи»
{sausage, whipped/sour cream} → {whole milk} (confidence 56%, lift 2.20) и
{frankfurter, yogurt} → {whole milk} (confidence 55%, lift 2.17) устроены так
же: мясное покупают «вместе с молоком», а не наоборот — направление
правила одностороннее.

                        4 Ограничения анализа
     Почему алкоголь и снеки не дали сильных правил. Алкоголь и
снеки — штучные импульсные позиции: их пары встречаются реже, чем в 50
чеках из 9 835, и порог support ≥ 0,5% отсекает такие связи как статистически
ненадёжные (при частоте ниже ~50 чеков confidence меняется на десятки
процентных пунктов от смены пары дней данных). Это не отсутствие связи, а
её недостаточная частота: сами связи могут быть выраженными, но редкими.
     Зачем удалять избыточные правила. Избыточное правило —
частный случай более общего ({A, B} → C при том же confidence, что и {A}
→ C); без очистки 1 362 правил из 12 181 — дублирующий шум,
искажающий приоритезацию по lift.

     Почему support — ключевая метрика для практики. Confidence и
lift можно «настроить» на любом сколь угодно редком правиле: пара из 3
чеков покажет confidence 100% и огромный lift без устойчивости и охвата.
Support — единственная метрика, связывающая правило с реальным потоком
чеков, поэтому бизнес-фильтрация начинается с порога support, и лишь затем
ранжируются confidence и lift.

     Наконец,    правила    фиксируют     совместность    покупок,    а   не
причинность (ассоциация ≠ причинность): управленческие решения из
раздела 4 — гипотезы для пилотной проверки (A/B-тест выкладки или
набора), а не гарантия роста продаж. Дополнительные ограничения: данные
одного месяца и одного магазина (нет сезонности и географии), отсутствие
количества и цены в чеке, пороги 0,5%/2 — консервативный компромисс
охвата и надёжности.

vegetables, yogurt} → {whole milk}, подчёркивая асимметрию ассоциативных
правил.

      Практическая ценность — готовые решения по выкладке, bundle-
наборам, ценовым якорям и промо-категориям; ограничение — порог support
≥ 0,5% отсекает редкие, но потенциально прибыльные связи (алкоголь,
снеки), для которых нужен либо больший объём данных, либо пониженный
порог.

# 9. Система рекомендаций (прямой + обратный вывод)
recommend_for_basket <- function(basket, rules, top_n = 10,
                                 exclude_in_basket = TRUE) {
  basket <- intersect(basket, itemLabels(Groceries))
  if (length(basket) == 0) return(cat("Товары не найдены в каталоге."))

  lhs_mat <- as(lhs(rules), "matrix")
  rhs_mat <- as(rhs(rules), "matrix")

  cols_lhs <- which(colnames(lhs_mat) %in% basket)
  cols_rhs <- which(colnames(rhs_mat) %in% basket)

  direct <- rep(FALSE, length(rules))
  if (length(cols_lhs) > 0) {
    n_lhs    <- rowSums(lhs_mat)

                                        15
        n_in_lhs <- rowSums(lhs_mat[, cols_lhs, drop = FALSE])
        direct   <- n_lhs > 0 & n_lhs == n_in_lhs
    }

    reverse <- rep(FALSE, length(rules))
    if (length(cols_rhs) > 0) {
      n_rhs    <- rowSums(rhs_mat)
      n_in_rhs <- rowSums(rhs_mat[, cols_rhs, drop = FALSE])
      reverse <- n_rhs > 0 & n_rhs == n_in_rhs
    }

    if (sum(direct) == 0 && sum(reverse) == 0) {
      return(cat("Правил для корзины не найдено."))
    }

    idx <- which(direct | reverse)
    idx_sorted <- idx[order(quality(rules[idx])$confidence, decreasing = TRUE)]

    items <- character(0)
    for (j in seq_along(idx_sorted)) {
      i <- idx_sorted[j]
      side <- if (direct[i]) labels(rhs(rules[i])) else labels(lhs(rules[i]))
      items <- c(items, trimws(strsplit(gsub("[{}]", "", side), ",")[[1]]))
      if (length(unique(items)) >= top_n * 2) break
    }
    items <- unique(items)

    if (exclude_in_basket) items <- setdiff(items, basket)
    if (length(items) == 0) return(cat("Все рекомендации уже в корзине."))

    cat("Корзина:", paste(basket, collapse = ", "), "\n")
    cat("Рекомендации:", paste(head(items, top_n), collapse = ", "), "\n")
    invisible(head(items, top_n))
}

rule_matches_category <- function(i, pat) {
  all_labels <- c(labels(lhs(strong_rules[i])),
                  labels(rhs(strong_rules[i])))
  sum(grepl(pat, all_labels)) >= 2
}

category_rule_counts <- integer(0)   # правка: кэш счётчиков для отчёта
for (cat_name in names(category_patterns)) {
  pat <- paste(category_patterns[[cat_name]], collapse = "|")
  keep <- vapply(seq_len(length(strong_rules)),
                 function(i) rule_matches_category(i, pat),
                 logical(1))
  cat_rules <- strong_rules[keep]
  category_rule_counts[cat_name] <- length(cat_rules)

  if (length(cat_rules) > 0) {
    top3 <- head(sort(cat_rules, by = "lift", decreasing = TRUE), 3)
    cat(sprintf("\n   [%s] — найдено %d правил, топ-3:\n",
                cat_name, length(cat_rules)))
    inspect(top3)
  } else {
    cat(sprintf("\n   [%s] — правил с support >= 0.5%% и >=2 товарами
категории не найдено\n",
                cat_name))
  }
}
