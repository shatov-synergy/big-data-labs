   — объяснена разница прямого и обратного поиска;
   — приведены минимум три практические бизнес-рекомендации;

    — R-скрипт с комментариями;

4. ОБЯЗАТЕЛЬНЫЕ AI4-МЕТОДЫ

В этом протоколе используются рабочие обозначения:

— AI4Dev: код, тесты и воспроизводимость.

Это рабочая классификация, а не утверждение о едином стандарте.
Если synergy-agent определяет эти методы иначе,
зафиксируй соответствие и различия.

Несколько ответов одной модели или несколько её ролей

Типы:

— численный результат;
— интерпретация;
— бизнес-гипотеза.

Проверяй:

— критерий избыточности;
— направление рекомендаций;
— объяснение отсутствия правил;
— обоснованность бизнес-выводов.

Используй документацию установленных версий пакетов.

Ищи не только подтверждение, но и опровергающие свидетельства.

4.2. AI4Dev

Применяй:

статический анализ → ожидаемое поведение →
тесты → безопасный запуск →
локализация → минимальный diff →
повторный тест → регрессионная проверка.

Виды тестов:

А. Модульные:
— фильтры правил;
— категории;
— recommend_for_basket;
— ранжирование и удаление повторов;
— экспорт.

Б. Граничные:
— пустая корзина;
— неизвестный товар;
— отсутствие правил;
— пустой результат категории;
— уже имеющийся товар;
— одинаковые кандидаты из нескольких правил.

В. Интеграционные:
Groceries → Apriori → фильтры → категории →
рекомендации → CSV.

Г. Регрессионные:
ранее корректные случаи после исправлений.

Д. Метаморфные:
— порядок товаров в корзине не влияет на результат,
  если корзина по смыслу является множеством;
— повышение порога support при фильтрации одного фиксированного
  набора правил не увеличивает число прошедших правил;
— добавление уже присутствующего товара повторно
  не меняет результат, если ввод трактуется как множество.

Для каждого свойства укажи условия.
Не переноси свойства простой фильтрации на полный пайплайн
с повторной генерацией или удалением избыточности.

Эталон теста получай независимо:
из определения, малого ручного примера,
отдельного расчёта или документации.

Не используй проверяемую функцию для генерации собственного эталона.

Фиксируй неудачные проверки и альтернативные объяснения.

4.5. AI4Reporting

— ограничения;

Оформление проверяй отдельно по прочитанным правилам.

Не исправляй текст так, чтобы скрыть ошибку расчёта.
