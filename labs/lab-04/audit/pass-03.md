## 3. Результаты

### 3.1. Категории (8.1) — ПОДТВЕРЖДЕНО, семантика установлена

Контрольные числа воспроизведены **семантикой кода**: `grepl` применяется
к вектору из двух строк-сторон правила (LHS-строка, RHS-строка), условие
`sum(...) >= 2` означает «совпадение **в обеих сторонах**», а не «≥2
товаров категории» (по-товарная трактовка даёт 114/24/3).

| Категория | rules | pruned | supp>0,5% | +lift>2 | Контроль |
|---|---|---|---|---|---|
| Фрукты-овощи | 2727 | 2455 | 97 | **86** | 86 ✓ |
| Завтрак | 1161 | 967 | 36 | **19** | 19 ✓ |
| Быстрый ужин | 138 | 112 | 5 | **3** | 3 ✓ |
| Выпечка | 32 | 31 | 0 | **0** | 0 ✓ |
| Алкоголь | 7 | 7 | 0 | **0** | 0 ✓ |
| Снеки | 29 | 29 | 0 | **0** | 0 ✓ |

Альтернативные причины отсутствия сильных правил (проверено
экспериментально): релевантные правила **есть у всех трёх «нулевых»
категорий** — Выпечка 31 (max supp 0,00285, max lift 18,61),
Алкоголь 7 (max supp 0,00468, max lift **35,72** — сильнейшая связь
датасета), Снеки 29 (max supp 0,00224, max lift 16,70) в pruned.
Причина нуля — **исключительно порог support > 0,005**, а не «редкие
связи» и не отсутствие правил после избыточности/фильтров. Формулировка
«нет сильных правил при данных порогах» — корректна; «связей в данных
нет» — некорректно (см. З-3.3 для текста отчёта).

Словарь: все паттерн-слова живые (в т.ч. popcorn). Особенности
подстрокового сопоставления: «butter milk» (пахта) матчит «Завтрак» через
`butter`; «curd cheese» попадает в «Выпечку» (curd) и «Завтрак»
(cheese); «instant coffee» — в «Быстрый ужин»; «fruit/vegetable juice»
двойной матч «Фруктов-овощей». Пересечений категорий на strong — 0
(сумма 108 ≤ 255 согласована). Числа 86/19/3 воспроизводятся именно с
этим словарём — код базовый, искажений нет.

### 3.2. recommend_for_basket (8.2) — ОБНАРУЖЕНО НЕСООТВЕТСТВИЕ (З-3.1)

**Поиск применимых правил корректен**: прямой = LHS ⊆ корзина,
обратный = RHS ⊆ корзина (проверено матрицей и эталоном; для
{whole milk} — 73 правила, для {whole milk, other vegetables} — 163).
Граничные случаи: пустая корзина и неизвестный товар → сообщение
«Товары не найдены в каталоге.» + NULL ✓; {white bread, butter} →
«Правил не найдено» ✓ (0 применимых strong-правил); {bottled beer,
red/blush wine} → «Правил не найдено» ✓ (правило есть в business,
supp 0,19% < 0,5%, в strong не входит — согласовано). Метаморфные:
перестановка и повтор товара не меняют вывод ✓ (intersect
уникализирует корзину).

**Извлечение рекомендаций сломано.** В цикле сбора кандидатов:

```r
items <- c(items, itemLabels(rhs(rules[i])))   # прямой
items <- c(items, itemLabels(lhs(rules[i])))   # обратный
```

`itemLabels()` для itemMatrix возвращает метки **всего каталога
(169 товаров)**, а не товары правила (нужен `labels()`). Доказательство
дебагом (pass3_debug.R, корзина {butter, whipped/sour cream},
3 применимых прямых правила: idx 44/97/236): `items` после цикла —
каталог ×3; `unique` → 169 товаров; `head(5)` → **frankfurter,
sausage, liver loaf, ham, meat — первые 5 товаров каталога**.
Вывод функции при наличии ≥1 применимого правила **не зависит ни от
корзины, ни от правил** — всегда первые top_n товаров каталога. Что и
наблюдалось: одинаковый список для 6 разных корзин.

Сопутствующий дефект (З-3.2): заявленная сортировка кандидатов по
confidence не действует —

```r
rec <- sort(rec, by = "confidence", decreasing = TRUE)
idx_sorted <- idx[order(rec@quality$confidence, decreasing = TRUE)]
```

`order()` по уже отсортированному вектору тождествен (1…n), поэтому
`idx_sorted = idx` — фактический порядок правил strong (по lift).
Дебаг: idx_sorted = 44 97 236 (lift 2,946 / 2,583 / 2,082) при
conf 0,57 / 0,66 / 0,40 — порядок lift, не confidence. Сейчас
ненаблюдаемо из-за З-3.1; станет видимым после его исправления.

Оба дефекта — в **базовом коде преподавателя** (diff прохода 2:
функция совпала с docx-исходником дословно).

### 3.3. Мясо и молоко (8.3)

Пересчёт по транзакциям: n(meat) = 254, n(meat∩whole milk) = 98 →
conf({meat}→{whole milk}) = **0,3858**, lift = **1,5100** — числа
аннотации («conf 39%, lift 1,51») верны. Направление: правило
{meat}→{whole milk} в **strong_rules отсутствует** (lift 1,51 < 2) —
следовательно в recommend_for_basket(strong_rules) оно даже не
участвует: «мясо» в рекомендациях — артефакт З-3.1 (5-й товар
каталога), а не следствие этого правила. Обратный confidence
P(meat | whole milk) = 0,0390 (функцией не показывается, подписей
метрик в выводе нет — п. «происхождение показанных метрик»: метрики
не показываются вовсе). Требование протокола «не превращать в
доказанное {молоко}→{мясо}» — выполнено: направление правила в
объяснениях не переворачивается (при исправлении З-3.1 «мясо» вообще
исчезнет из рекомендаций для {молоко, овощи} — топ по conf:
tropical fruit, pip fruit, butter, root vegetables, citrus fruit).

### 3.4. Автоматические рекомендации (8.4) — ПОДТВЕРЖДЕНО

Все 6 категорий обрабатываются автоматическим циклом; пустые
сообщаются явно («правил … не найдено»); товары в текстах — только
из найденных правил (топ-3 категорий в логе совпадают со сверкой,
например {butter, whipped/sour cream} => {whole milk} 0,0067/0,66 —
есть в strong_rules.csv). Блок 10.4 (обратный вывод для молока):
топ-3 по conf = {tropical fruit, root vegetables, yogurt} (70%),
{pip fruit, root vegetables, other vegetables} (68%), {butter,
whipped/sour cream} (66%) — лог = пересчёт ✓; направление в подписи
описано корректно («правила вида {X, Y} → {молоко}… Обратный вывод,
а не „молоко тянет X“»). {sausage, whipped/sour cream} → {whole milk}
(conf 0,5618, lift 2,1987, supp 0,508%) в strong_rules.csv есть —
упоминание в аннотации корректно.

## 4. Реестр замечаний (новые)

- **З-3.1 (существенное).** `recommend_for_basket`: извлечение
  кандидатов через `itemLabels(lhs/rhs(...))` возвращает весь каталог
  (169 товаров), а не товары правила → функция всегда выдаёт первые
  top_n товаров каталога (frankfurter…meat), вывод не зависит от
  корзины и правил. Файл `task1_groceries_apriori.R:142,144`; код
  базовый (задание: «запустите предоставленный R-скрипт»). Влияние:
  раздел примеров отчёта и центральный пример «мясо для {молоко,
  овощи}» не отражают реальную работу правил. Минимальное исправление:
  `itemLabels(rhs(rules[i]))` → `gsub("[{}]","",labels(rhs(rules[i])))`
  (аналогично lhs) — тогда для {butter, whipped/sour cream} вывод
  станет «other vegetables, whole milk». Способ повторной проверки:
  тесты pass3 (эталон). Критичность именно существенная (не
  критическая): контрольные числа пайплайна, CSV и метрики не
  затронуты; сломан алгоритм одной функции и корректность одного
  раздела отчёта. Статус: открыто.
- **З-3.2 (незначительное, проявится после исправления З-3.1).**
  Сортировка кандидатов по confidence не работает (двойная
  сортировка, `idx_sorted = idx`, фактический порядок — lift).
  `task1_groceries_apriori.R:135-136`. Минимальное исправление:
  `idx_sorted <- idx[order(quality(rules[idx])$confidence,
  decreasing = TRUE)]`. Статус: открыто.
- **З-3.3 (перенос в проход 5 — формулировки отчёта).** (а)
  Объяснение «мясо — правило {мясо}→{молоко}»: механически неверно
  (З-3.1; правило не входит в strong); продиктовано текстом задания,
  но в отчёте требуется корректная формулировка. (б) «Редкие связи»
  как причина отсутствия правил алкоголя/выпечки/снеков: связь
  алкоголя — сильнейшая в датасете (lift до 35,7); причина — порог
  support 0,5%. Статус: открыто до сверки PDF.
