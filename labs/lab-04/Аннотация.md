## Постановка задачи

Две задачи. **Задача 1** — анализ потребительской корзины датасета
Groceries (9835 транзакций, 169 товаров): Apriori (support = 0,001,
confidence = 0,3), удаление избыточных правил, бизнес-правила
(lift > 1,2), сильные (support ≥ 0,5%, lift > 2), визуализации,
рекомендательная функция с прямым и обратным выводом, бизнес-рекомендации
по шести категориям; отчёт с объяснением support/confidence/lift и
разделом «Ограничения». **Задача 2** — прогнозирование продаж категории
«Овощи - Фрукты» из Magazin.xlsx (1096 дней, 01.01.2023–31.12.2025):
шесть моделей (Prophet base, Prophet + погода, Prophet + погода + цена,
ETS, SARIMA, ансамбль) с экспериментальным подбором параметров и
сравнением по RMSE/MAE/MAPE на тесте последних 30 дней. Дополнительно по
методологии AI4Research (arXiv:2507.01903): корреляционный анализ
погодных условий (реальные дневные данные ВДНХ с осадками, Open-Meteo
Archive API) и цен (колонка Price), а также макро-контекст потребления
фруктов и овощей (НЦСЭД/ОЭСР, DF_HEALTH_LVNG_FSC).

## Что сделано

1. **Задача 1** (`labs/lab-04/task1_groceries_apriori.R`, код
   преподавателя дословно + техправки): 12 181 правило → 10 819 после
   удаления избыточных; бизнес-правил 10 736, сильных 255. Рабочие
   категории: Фрукты-овощи (86 правил), Завтрак (19), Быстрый ужин (3);
   Выпечка/Алкоголь/Снеки — 0 (support < 0,5%). Ключевое правило
   {citrus fruit, other vegetables, whole milk} → {root vegetables}
   (lift 4,1); обратный вывод разобран на корзине {молоко, овощи} →
   мясные товары ({meat} → {whole milk}, conf 39%, lift 1,51).
2. **Задача 2, корреляционный анализ (AI4Research)**: сумма двух
   источников сверх файла задания — погода ВДНХ (Open-Meteo, осадки
   в 648 днях из 1096; согласованность температуры файла и ВДНХ
   r = 0,981) и макро-датасет НЦСЭД/ОЭСР (фрукты/овощи, кг/чел/год,
   РФ 1992–2021). Итоги: значимый погодный канал — осадки (в дождь
   продажи ниже на ~30 шт. ≈ 3,9%, p = 0,0006; частная корреляция
   −0,065); температура после контроля дня недели и месяца эффекта не
   имеет (частная −0,007, «сырая» связь −0,28 — сезонность); цена —
   сильнейший фактор после календаря (частная корреляция −0,479,
   log-log эластичность −0,286 — спрос неэластичен). Макро-контекст:
   потребление овощей 80,1 → 112,5 и фруктов 39,9 → 80,3 кг/чел/год
   (1992→2021), cor(FRS, VGS) = 0,913 — категория структурно растущая.
3. **Задача 2, подбор параметров**: этап A — weekly.seasonality = 3
   (ровный недельный профиль ±5%, как и предписывает задание для
   «ровных» категорий), этап B — n.changepoints = 40, этап C —
   seasonality 0,5 / changepoint 0,05 / holidays 5. Абляция pre_new_year:
   RMSE 94,5 с праздником против 113,9 без — оставлен (предновогодний
   подъём есть и у овощей-фруктов). ETS: лучшая AAA (A,Ad,A) 87,4;
   SARIMA — авто при frequency = 7, D = 1.
4. **Итог теста (30 дней, RMSE/MAE/MAPE):** Ensemble (Prophet + ETS)
   68,3/56,0/8,8% < ETS (AAA) 87,4/61,7/9,4% < Prophet base
   94,5/74,1/11,2% < Prophet + погода 96,4 < SARIMA 97,3 < Prophet +
   погода + цена 97,8. Регрессоры на коротком окне не улучшают Prophet
   (эффекты уже в календарных компонентах); ансамбль гасит
   разнонаправленные смещения Prophet и ETS. Диагностика остатков:
   Ljung-Box (lag 14, fitdf = 0) значим у всех моделей, у Ensemble
   слабее (p ≈ 0,0002).
5. **Отчёты по ГОСТ 7.32-2017** (два, по одному на задачу): титульный
   лист-форма «Синергии» (преподаватель — Дзизинская Д. В.),
   СОДЕРЖАНИЕ с фактическими номерами, числа — inline-R из расчётов.
   Задача 1 — 15 стр. (4 рисунка, 4 таблицы); задача 2 — 22 стр.
   (11 рисунков, 8 таблиц).

## Главный результат

**Для «Овощи - Фруктов» дневной объём управляется календарём и ценой,
а не погодой как таковой.** Температурная связь — сезонность (частная
корреляция после контроля дня недели и месяца ≈ 0); единственный
собственно-погодный эффект — дождь (−3,9% продаж, планирование
выкладки и персонала); цена — сильнейший управляемый фактор (частная
корреляция −0,48, эластичность −0,29: спрос неэластичен, ценовой рычаг
меняет объём покупки, а не факт покупки). Лучший прогноз на 30 дней —
ансамбль Prophet + ETS (MAPE 8,8%), внешние регрессоры на коротком
горизонте избыточны. Макро-данные ОЭСР подтверждают структурный рост
категории — точность её локального прогноза окупается.

## Воспроизведение

Всё выполнялось в Docker (контейнер `lab04` из образя
`big-data-labs-rstudio` на базе rocker/rstudio R 4.6.1; пакеты
практикума — в `docker/install_pkgs.R`):

```bash
docker exec lab04 bash -c \
  "cd /project/labs/lab-04 && Rscript task1_groceries_apriori.R && Rscript task2_magazin_ovoshchi_frukty.R"
docker exec lab04 Rscript -e \
  'rmarkdown::render("labs/lab-04/zadacha1_report.Rmd", output_dir="labs/lab-04/output")'
# титульник/СОДЕРЖАНИЕ: templates/apply_title_page.py (--lab 4 --toc),
# номера — двухпроходно по PDF; финал: docker exec lab04 bash labs/lab-04/finalize.sh
```

Погодный кэш качается скриптом сам (https-запрос только к
archive-api.open-meteo.com, при наличии кэша не повторяется);
макро-датасет уже в `data/`. Технические правки относительно
методических кодов преподавателя документированы в шапках скриптов
(целиком: чтение из `data/`, сохранение Price, PNG-обёртки, MAPE в
процентах, ds→Date, детект регрессоров `m$extra_regressors`,
Ljung-Box fitdf = 0, частные корреляции с контролем дня недели и
месяца).
