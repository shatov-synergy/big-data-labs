# Аннотация. Лабораторный практикум 4

Дисциплина «Продвинутые технологии работы с большими данными»,
Университет «Синергия». Выполнено 12 ноября 2026 г.

## Постановка задачи

Две задачи. **Задача 1** — анализ потребительской корзины датасета
Groceries (9835 транзакций, 169 товаров): Apriori (support = 0,001,
confidence = 0,3), удаление избыточных правил, бизнес-правила
(lift > 1,2), сильные (support ≥ 0,5%, lift > 2), визуализации,
рекомендательная функция с прямым и обратным выводом, бизнес-рекомендации
по шести категориям; отчёт 5–7 стр. с объяснением support/confidence/lift
и разделом «Ограничения». **Задача 2** — прогнозирование продаж категории
«Алкоголь» из Magazin.xlsx (1096 дней, 01.01.2023–31.12.2025): пять моделей
(Prophet base, Prophet + weather, ETS, SARIMA, ансамбль) с обязательным
экспериментальным подбором параметров и сравнением по RMSE/MAE/MAPE на
тесте последних 30 дней (декабрь 2025 с предновогодним окном).

## Что сделано

1. **Задача 1** (`labs/lab-04/task1_groceries_apriori.R`, код
   преподавателя дословно + техправки): найдено 12 181 правило,
   избыточных 1 362, после очистки 10 819; бизнес-правил 10 736,
   сильных 255. Товары-магниты: whole milk 25,6%, other vegetables
   19,3%, rolls/buns 18,4%. Рабочие категории: Фрукты-овощи (86 правил),
   Завтрак (19), Быстрый ужин (3); Выпечка/Алкоголь/Снеки — 0 правил
   (support < 0,5%). Ключевое правило: {citrus fruit, other vegetables,
   whole milk} → {root vegetables} (lift 4,1). Обратный вывод разобран на
   корзине {молоко, овощи} → мясные товары (правило {meat} → {whole milk},
   conf 39%, lift 1,51, и сильные {sausage, whipped/sour cream} →
   {whole milk}). CSV-выгрузка — output/Groceries_results/.
2. **Задача 2** (`labs/lab-04/task2_magazin_alko.R`, базовый код
   преподавателя + поэтапный эксперимент по заданию): этап A
   (weekly.seasonality 3/5/10/15) → 10; этап B (n.changepoints 15/25/40)
   → 15; этап C (2×2×3 prior scale'ов) → seasonality 0,5,
   changepoint 0,01, holidays 1; абляция pre_new_year: RMSE 19,5 против
   35,9 шт. без праздника (в 1,8 раза хуже) — праздник обязателен и
   подтверждён. ETS: авто M,N,M (RMSE 39,1) против AAA 39,8 / MAM 39,6 /
   MNM 39,1. SARIMA — авто при frequency = 7, D = 1.
3. **Итог теста (30 дней, RMSE/MAE/MAPE):** Prophet (base + pre-NY)
   19,5/14,9/8,8% < Prophet (+ weather) 20,9/15,9/9,2% < Ensemble
   24,6/18,0/9,7% < ETS 39,1/24,1/12,1% < SARIMA 46,2/30,5/15,4%.
   Погодный регрессор не улучшает прогноз; ETS/SARIMA проигрывают из-за
   отсутствия годовой сезонности и праздников на декабрьском тесте.
   Диагностика остатков (checkresiduals, Ljung-Box lag 14): у всех моделей
   p ≈ 0 (годовая структура вне недельных моделей); у Prophet ACF «грязнее»
   на малых лагах — нет AR-компоненты.
4. **Отчёты по ГОСТ 7.32-2017** (два, по одной на задачу): титульный
   лист-форма «Синергии», СОДЕРЖАНИЕ с фактическими номерами, ВВЕДЕНИЕ,
   нумерованные разделы, ВЫВОДЫ; в задаче 1 — 4 рисунка и 4 таблицы,
   в задаче 2 — 6 рисунков и 6 таблиц; все числа — inline-R из расчётов.
   15 и 17 страниц.

## Главный результат

**Для категории «Алкоголь» решающим фактором прогноза является календарная
структура спроса, а не погода.** Подобранный Prophet (порядок Фурье
недельной сезонности 10 под резкий пятничный пик, жёсткий тренд
changepoint.prior.scale 0,01 при n.changepoints 15, праздник pre_new_year
28–31 декабря) снижает RMSE декабрьского теста до 19,5 шт. (MAPE 8,8%) —
в 1,8 раза лучше, чем без праздника, и в 2,4 раза лучше ETS/SARIMA,
которые видят только недельный цикл. Практический вывод для управления
запасами: заказ алкоголя на предновогоднее окно строится на модели с
явными праздниками и годовой сезонностью; остатки Prophet
автокоррелированы (нет AR-компоненты), поэтому интервалы расширяются
страховым запасом.

## Воспроизведение

Всё выполнялось в Docker (контейнер `lab04` из образа
`big-data-labs-rstudio` на базе rocker/rstudio R 4.6.1; пакеты практикума
— в `docker/install_pkgs.R`, пересборка: `docker compose build`):

```bash
docker exec lab04 bash -c \
  "cd /project/labs/lab-04 && Rscript task1_groceries_apriori.R && Rscript task2_magazin_alko.R"
docker exec lab04 Rscript -e \
  'rmarkdown::render("labs/lab-04/zadacha1_report.Rmd", output_dir="labs/lab-04/output")'
# титульник/СОДЕРЖАНИЕ: templates/apply_title_page.py (--lab 4 --toc),
# номера — двухпроходно по PDF; финал: bash labs/lab-04/finalize.sh
```

Технические правки относительно методических кодов преподавателя
(задокументированы в шапках скриптов): чтение данных из `data/`,
сохранение графиков в `output/`, PNG-обёртки для base-графиков arulesViz,
переводы строк в `cat()`, разбор колонки `rules` в отчёте, MAPE
в процентах (yardstick уже возвращает %), `ds` приведён к Date после
bind_rows, детект регрессора через `m$extra_regressors`, Ljung-Box с
единым fitdf = 0. Пакет `holidays` не используется: prophet содержит
данные праздников сам, а с CRAN он недоступен для R 4.6.1.
