# Стандарты оформления отчётов по лабораторным работам
## Университет «Синергия»

> Стандарты извлечены из утверждённых отчётных документов обучающегося
> (отчёты по лабораторным работам и выпускная квалификационная работа).
> Этот файл — единый источник правил: по нему нейросеть собирает docx-отчёт
> по любому заданию без просмотра примеров.

## 1. Параметры страницы

| Параметр | Значение |
|---|---|
| Формат | A4 портрет (21 × 29,7 см) |
| Поля | верх 2 см, низ 2 см, **лево 3 см**, право 1,5 см |
| Колонтитулы | 1,25 см |
| Нумерация страниц | не используется в лабораторных отчётах |

## 3. Титульный лист — структурный клон титульного листа ВКР

Строится функцией `add_title_page` (templates/synergy_docx.py) и вставляется
в R Markdown-отчёты скриптом `templates/apply_title_page.py`. Всё — Times
New Roman, одинарный интервал; значения форм подчёркнуты **нижней границей
ячейки** безрамочной таблицы (как в образце).

```
НЕГОСУДАРСТВЕННОЕ ОБРАЗОВАТЕЛЬНОЕ ЧАСТНОЕ УЧРЕЖДЕНИЕ ВЫСШЕГО ОБРАЗОВАНИЯ
«МОСКОВСКИЙ ФИНАНСОВО-ПРОМЫШЛЕННЫЙ УНИВЕРСИТЕТ «СИНЕРГИЯ»»      (2-я строка полужирная)

Факультет Информационных технологий          («Информационных технологий» подчёркнуто, 15 пт)

┌─ безрамочная форма-таблица ─────────────────────────────────────────┐
│ Направление подготовки:  09.03.02 Информационные системы и технологии│ ← подчёркнуто
│                          (код, наименование)          10 пт курсив   │
│ Кафедра  ИИиАД ← подчёркнуто   (аббревиатура) 10 пт курсив           │
│ Профиль:  Разработка, сопровождение и обеспечение безопасности       │
│           информационных систем ← подчёркнуто на всю ширину          │
└──────────────────────────────────────────────────────────────────────┘

        ОТЧЕТ ПО ЛАБОРАТОРНОЙ РАБОТЕ № N               (16 пт, полужирный)
        по дисциплине «НАЗВАНИЕ ДИСЦИПЛИНЫ»            (полужирный)
        на тему  «ТЕМА» ← подчёркнуто, полужирно

   Обучающийся  Фамилия Имя Отчество (полужирный курсив)
                (Фамилия Имя Отчество)   (подпись)     (8 пт курсив)
   Группа       XXX-000
   Преподаватель  _
                (Фамилия Имя Отчество)   (подпись)

                МОСКВА 2026 г.      (полужирный, год подчёркнут)
```

Раздел отчёта начинается с новой страницы (стиль Заголовка 1).

## 4. Структура отчёта по ГОСТ 7.32-2017

1. **Титульный лист** (раздел 3) — страница 1, номер не проставляется
   (но учитывается в сквозной нумерации).
2. **СОДЕРЖАНИЕ** — страница 2: заголовок полужирно по центру КАПСОМ,
   перечень разделов/подразделов с точечными лидерами и номерами страниц
   справа; подразделы с отступом 0,75 см. Само содержание в перечень
   не включается.
3. **ВВЕДЕНИЕ** — структурный элемент: КАПСОМ, по центру, полужирно,
   БЕЗ номера, с новой страницы. Содержит условие задачи и цель работы.
4. **Разделы** — сквозная нумерация арабскими цифрами БЕЗ точки в конце
   номера: `1 Название`, подразделы `1.1 Название`, `1.1.1 Название`.
   Каждый раздел — с новой страницы. Наименования содержательные
   (не «Ход решения»).
5. **ВЫВОДЫ** — структурный элемент (как ЗАКЛЮЧЕНИЕ по ГОСТ): КАПСОМ,
   по центру, без номера, с новой страницы.
6. **Нумерация страниц** — арабскими цифрами, по центру нижнего колонтитула,
   сквозная с титульного листа (на титуле не ставится).

Внутри каждого пункта анализа сохраняется схема:

```
Условие (текст задания, допускается курсив)
Код решения                (Courier New 10, серый фон)
Результат выполнения       (вывод R: Courier New 10, без фона)
Рисунки/таблицы            (см. раздел 5)
Гипотезы: H₀ — ...; H₁ — ...          (для статистических тестов)
Интерпретация: ...                     (полужирная метка + текст)
Вывод: ...                             (полужирная метка + текст)
```

## 5. Иллюстрации и таблицы (ГОСТ 7.32-2017, пп. 6.4–6.5)

- Рисунок — **строго по центру** страницы (без красной строки у абзаца
  с изображением; в Rmd центрируется скриптом `apply_title_page.py`,
  в python-API — стилем Figure).
- Подпись под рисунком: `Рисунок N — Название` — по центру, полужирно,
  14 пт; разделитель — **тире**, без точки в конце.
- **В тексте обязательна ссылка на каждый рисунок** — «(рисунок 3)».
- Подпись таблицы: `Таблица N — Название` — ОДНОЙ строкой над таблицей,
  слева, без абзацного отступа, полужирно. **В тексте обязательна ссылка**
  «(таблица 2)».
- Таблица: все границы ячеек одинарные, шапка полужирная по центру 12 пт,
  текст ячеек 12 пт, одинарный интервал; у сводных таблиц — итоговая строка.
- Нумерация рисунков и таблиц — сквозная в пределах одного отчёта.

## 6. Списки

- Маркированный: тире «–» с последующим пробелом (не маркер Word).
- Нумерованный: цифра с точкой «1. », набирается текстом.
- Перечисления внутри ответов: «a. », «b. » и т.д.

## 7. Генерация docx

### Вариант А — python-docx (без R, любой предмет)

```python
from synergy_docx import SynergyReport

r = SynergyReport(discipline="...", topic="...", lab_number=1,
                  group="ВБИо-403-рсоб")
r.heading("1 Задание 1. Название", 1)
r.paragraph("Условие...")
r.code("library(ggplot2) ...")        # код
r.output("... вывод R ...")           # результат
r.figure("output/plot.png", "Подпись")# рисунок + автонумерация
r.table([["A","B"],["1","2"]], caption="Название")  # таблица
r.hypotheses("средние равны", "средние различаются")
r.interpretation("p < 0,05 ...")
r.conclusion("...")
r.save("labs/lab-01/output/report.docx")
```

Пример запуска: `python templates/generate_report.py`.

### Вариант Б — R Markdown (для R-лабораторных, автоматические результаты)

В YAML-заголовке отчёта:

```yaml
output:
  word_document:
    reference_docx: reference.docx   # шаблон стилей из templates/
```

`reference.docx` собирается скриптом `python templates/build_templates.py`.

## 8. Состав результата практикума

По каждой задаче практикума оформляется **отдельный отчёт** — файлы
`Laboratornyiy praktikum N_Задача M_отчет.docx` и `.pdf` (pdf — конвертация
docx, например LibreOffice: `soffice --headless --convert-to pdf file.docx`).
