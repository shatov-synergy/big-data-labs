# AGENTS.md — правила для ИИ-агентов и нейросетей

Проект: лабораторные работы по дисциплине «Продвинутые технологии работы
с большими данными», Университет «Синергия». Всё выполняется в RStudio
Server внутри Docker; результаты и отчёты хранятся в этом репозитории.

**Язык**: все тексты, отчёты, коммит-сообщения и ответы обучающемуся —
на русском языке. Код и идентификаторы — на английском.

## Структура репозитория

```
assignments/lab-NN/   исходные задания (docx) — только на чтение
labs/lab-NN/          рабочая папка лабораторной N:
  taskM_*.R           скрипты задач (пишут графики в output/)
  zadachaM_report.Rmd исходники отчётов (по одному на задачу)
  reference.docx      стили отчёта (НЕ редактировать руками — генерируется)
  output/             графики, интерактивные html, отчёты docx+pdf
data/                 кэш внешних данных (котировки TSLA) — не удалять
templates/            система оформления отчётов (см. ниже)
docker/               скрипты сборки образа
```

## Окружение и команды

- Запуск RStudio: `docker compose up -d --build` → http://localhost:8787
  (логин `rstudio`, пароль из `.env`, по умолчанию `bigdata`).
- Весь репозиторий примонтирован в контейнер как `/home/rstudio/project`.
- Headless-прогон скрипта:
  `docker compose run --rm rstudio bash -lc "cd labs/lab-01 && Rscript task1_diamonds.R"`
- Рендер отчёта (docx) — см. скилл `render-reports`.
- Образ: `rocker/rstudio:4.6.1` + пакеты из `docker/install_pkgs.R`.

**Сетевые особенности (важно)**: из Docker-контейнеров в сети владельца
недоступны p3m.dev (P3M/Posit) и частично cloud.r-project.org — загрузки
«зависают». Рабочие зеркала CRAN из контейнеров:
`cran.ma.imperial.ac.uk`, `mirrors.tuna.tsinghua.edu.cn/CRAN`,
`mirror.las.iastate.edu/CRAN`. Скрипт установки уже перебирает их сам.
При ошибках сети сначала проверь доступность зеркала, потом меняй код.
Сборка образа требует системных пакетов apt: `cmake`, `libcurl4-openssl-dev`,
`libxml2-dev`, `libuv1-dev` (для nloptr, curl, fs) — уже в Dockerfile.

## Отчёты — главный продукт репозитория

**Единый источник стандартов: [`templates/REPORT_STANDARDS.md`](templates/REPORT_STANDARDS.md).**
Перед любой работой с отчётами прочитай его целиком. Ключевое:

- По каждой задаче практикума — **отдельный отчёт**, файлы
  `Laboratornyiy praktikum N_Задача M_отчет.docx` и `.pdf` в `labs/lab-NN/output/`.
- Оформление — клон утверждённых образцов Синергии (ГОСТ 7.32-2017):
  A4, поля 2/1,5/2/3 см; TNR 14; полуторный интервал; по ширине; красная
  строка 1,25 см; заголовки 16/14 пт полужирные по центру, раздел с новой
  страницы; код Courier New 10 на сером фоне; вывод R — Courier New 10.
- Титульный лист — форма: метки полужирные, значения ПОДЧЁРКНУТЫЕ,
  подсказки 9 пт, внизу «Москва <год> г.».
- Подписи рисунков: «Рисунок N. Название» — полужирно, по центру, ПОД рисунком.
- Подписи таблиц: две строки НАД таблицей — «Таблица N» справа полужирно,
  название по центру полужирно с точкой в конце.
- В тексте обязательны ссылки «(рисунок N)» / «(таблица N)» и аналитика:
  для тестов — блоки «Гипотезы: H₀ —…; H₁ —…» → «Интерпретация:…» → «Вывод:…».
- Числа в выводах подставлять фактическими значениями (inline-R в Rmd),
  а не сочинёнными.

Шаблоны `templates/report_template.docx` и `reference.docx` генерируются
скриптом `python templates/build_templates.py` — не редактировать их руками,
менять `templates/synergy_docx.py` и пересобирать.

## Запрещено

- Коммитить `.env`, `docker/build.log`, `__pycache__`, `_verify/`, `Rplots.pdf`.
- Удалять/перезаписывать `data/*.csv` (кэш котировок) без явной просьбы.
- Вставлять в отчёты выдуманные численные результаты — только вывод расчётов.
- Менять `assignments/` (исходные задания) и чужие docx-образцы.
- `git push --force`, переписывание истории.

## Конвенции

- Коммиты: краткое описание на русском, что и зачем
  («Отчёт задачи 2: исправлена подпись таблицы 3»).
- Новая лабораторная — по скиллу `new-lab` (структура как у `labs/lab-01`).
- Имена файлов сдачи — строго `Laboratornyiy praktikum N_Задача M_отчет.{docx,pdf}`.
- PDF получается только конвертацией итогового docx (LibreOffice в контейнере).

## Общий набор synergy-agent

Если рядом есть каталог `../synergy-agent`, финальные pptx и docx перед
сдачей прогонять через `../synergy-agent/scripts/sanitize_ooxml.py` и
`../synergy-agent/scripts/validate_office.py`. Шаблон Синергии не отдавать
как файл сдачи. Файл, пересохранённый в OnlyOffice, не сдавать.

## Скиллы проекта (`.agents/skills/`)

| Скилл | Когда применять |
|---|---|
| `new-lab` | подготовить структуру новой лабораторной работы |
| `render-reports` | пересобрать docx/pdf отчёты в Docker |
| `synergy-report` | сверка/генерация отчёта по стандартам Синергии |
